# TECHNOLOGIES_GUIDE — справочник по `technologies.json` и связанным системам

Документ для разработки: что означает каждое поле JSON, как оно читается кодом и какие побочные эффекты имеет.  
Основные файлы кода:

| Файл | Роль |
|------|------|
| `technologies.json` | Каталог: meta, этапы, категории, группы, технологии |
| `technologies.js` | Панель «Наука», дерево, прогресс, модалка, сейвы |
| `technologiesExtras.js` | Чипы активных исследований в хэдере + блок характеристик |
| `technologiesGraph.js` | SVG-рёбра между карточками (locked / active / boost) |
| `state.techProgress` | Рантайм: `{ [techId]: { level, invested, researching } }` |

Языки интерфейса: `ru` / `en` / `de` (через `getLang()` + `pick()` / `t()`).

---

## 1. Корень файла

```json
{
  "meta": { ... },
  "stageDefs": [ ... ],
  "categories": [ ... ],
  "groups": [ ... ],
  "technologies": [ ... ]
}
```

| Ключ | Тип | Назначение |
|------|-----|------------|
| `meta` | object | Размеры карточек/мира, картинка блока «Улучшить» |
| `stageDefs` | array | Справочник **этапов развития** (цвет + локализованное имя) |
| `categories` | array | Разделы левого сайдбара (Фундаментальные, Транспортные, …) |
| `groups` | array | Подразделы внутри категории (таблички на дереве) |
| `technologies` | array | Сами технологии (карточки + логика) |

## 2. `meta`

```json
"meta": {
  "version": 2,
  "cardWidth": 132,
  "cardHeight": 148,
  "gapX": 56,
  "gapY": 36,
  "padX": 64,
  "padY": 64,
  "minWorldW": 1800,
  "minWorldH": 1200,
  "upgradeImage": "assets/textures/technologies/scientist_microscope.png"
}
```

| Поле | Смысл |
|------|--------|
| `version` | Версия схемы каталога (для будущих миграций) |
| `cardWidth` / `cardHeight` | Размер карточки на дереве (px). Использует `cardSize()` |
| `gapX` / `gapY` | Зазоры между колонками/строками внутри группы |
| `padX` / `padY` | Внутренние отступы мира дерева |
| `minWorldW` / `minWorldH` | Минимальный размер «мира» для панорамирования (в коде может быть свой floor) |
| `upgradeImage` | PNG для декора в контейнере «Улучшить технологию» |

Менять размеры карточек здесь — предпочтительнее, чем хардкодить в CSS (обёртка `.tech-card-wrap` всё ещё имеет дефолтные 132×148 в CSS; при смене meta сверяй CSS).

## 3. `stageDefs[]` — этапы развития

Список **глобальных** этапов. Цвет рамки уровня в модалке и подпись («Базовая», «Продвинутая», …) берутся отсюда; **какие уровни технологии попадают в какой этап** задаёт уже `technologies[].stageRanges`.

```json
{
  "id": "basic",
  "color": "#8b6914",
  "name": { "ru": "Базовая", "en": "Basic", "de": "Basis" }
}
```

| Поле | Смысл |
|------|--------|
| `id` | Ключ этапа: `none`, `basic`, `primitive`, `advanced`, `super`, `divine` |
| `color` | CSS-цвет рамки «уровень / этап» в модалке (`--stage-color`) |
| `name` | Локализованное имя этапа |

`resolveStage(tech)`: смотрит `tech.level` и `tech.stageRanges[id] = [min, max]` (включительно). Если уровень 0 → обычно `none`.

## 4. `categories[]` — разделы сайдбара

```json
{
  "id": "transport",
  "order": 2,
  "icon": "assets/textures/technologies/cat_transport.svg",
  "name": { "ru": "Транспортные", "en": "Transport", "de": "Transport" }
}
```

| Поле | Смысл |
|------|--------|
| `id` | Идентификатор категории. Связь: `technologies[].categoryId`, `groups[].categoryId` |
| `order` | Порядок кнопок в левом сайдбаре (меньше → выше) |
| `icon` | Путь к SVG/PNG иконке кнопки |
| `name` | Локализованное название раздела |

Активна **одна** категория за раз (`activeCategory`). Дерево и графы строятся только по технологиям этой категории.

Текущий набор id (ориентир):  
`fundamental`, `infrastructure`, `transport`, `raw`, `production`, `energy`, `military`.

## 5. `groups[]` — подразделы на дереве

Группы рисуются **вертикально** (стопкой): подпись группы + горизонтальная градиентная линия, ниже — сетка карточек этой группы.

```json
{
  "id": "atmo_suborbit",
  "categoryId": "transport",
  "order": 0,
  "column": 0,
  "row": 0,
  "name": {
    "ru": "Атмосферное / суборбитальное",
    "en": "Atmospheric / suborbital",
    "de": "Atmosphärisch / suborbital"
  }
}
```

| Поле | Смысл |
|------|--------|
| `id` | Id группы. Связь: `technologies[].groupId` |
| `categoryId` | В какой категории показывать группу |
| `order` | Порядок блоков сверху вниз внутри категории |
| `column` / `row` | Зарезервированы под будущую 2D-раскладку групп; сейчас раскладка в основном по `order` |
| `name` | Подпись на дереве |

Технологии **без** `groupId` или с неизвестным id попадают в «сиротский» блок внизу.

## 6. `technologies[]` — карточка технологии

### 6.1 Идентификация и размещение

| Поле | Тип | Смысл |
|------|-----|--------|
| `id` | string | Уникальный id (`TECH_PHYSICS`, `TECH_ICE`, …). Ключ в `state.techProgress` и сейвах |
| `categoryId` | string | Раздел сайдбара |
| `groupId` | string | Подраздел на дереве |
| `column` | int ≥ 0 | **Локальная** колонка внутри группы (0 = левее) |
| `row` | int ≥ 0 | **Локальная** строка внутри группы (0 = выше) |
| `image` | string | Путь к артам карточки / большой аватарки в модалке |
| `discovered` | bool | Если `false` — всегда «неизвестная» (поверх gate родителей). Обычно `true` |

`column`/`row` считаются **внутри группы**, не глобально по всему дереву. Абсолютные px считает `layoutCategory()`.

### 6.2 Имена и тексты

| Поле | Тип | Смысл |
|------|-----|--------|
| `name` | `{ru,en,de}` | Название на карточке, в модалке, в чипах «активных исследований» |
| `description` | `{ru,en,de}` | Текст в правом верхнем блоке модалки (со скроллом) |

### 6.3 Уровни и стоимость

| Поле | Тип | Смысл |
|------|-----|--------|
| `level` | int | **Стартовый** уровень из JSON (сид для новой игры). После старта источник истины — `state.techProgress[id].level` |
| `maxLevel` | int | Потолок прокачки. При `level >= maxLevel` исследование останавливается |
| `levelCosts` | number[] | Стоимость **перехода** с уровня `i` на `i+1` в **ед. технологий** (потоковый `RES_TECH_OUTPUT`). Индекс = текущий уровень: `levelCosts[0]` = цена 0→1, `levelCosts[1]` = 1→2, … |

Пример: `maxLevel: 8`, массив из 8 чисел → можно сделать 8 апгрейдов (0→1 … 7→8).

`getLevelCost(tech, level)` возвращает `levelCosts[level]` или `null`, если дальше нельзя.

### 6.4 Этапы по уровням (`stageRanges`)

```json
"stageRanges": {
  "none": [0, 0],
  "basic": [1, 2],
  "primitive": [3, 4],
  "advanced": [5, 6],
  "super": [7, 7],
  "divine": [8, 8]
}
```

| Ключ | Смысл |
|------|--------|
| каждый id из `stageDefs` | Пара `[minLevel, maxLevel]` **включительно**. Уровень технологии попадает ровно в один диапазон |

Цвет и имя этапа в модалке = `stageDefs` + текущий `level` из прогресса.

### 6.5 Устаревшие / вспомогательные связи

| Поле | Тип | Смысл |
|------|-----|--------|
| `prerequisites` | string[] | Упрощённый список id родителей. **Fallback**, если нет `requirements`. Также используется графом и UI как доп. источник рёбер |
| `unlocks` | string[] | Явный список детей, которых эта технология «открывает» (для графа и блока «Открывает»). Не заменяет `requirements` у детей |

Для новой логики **главный** источник — `requirements` (ниже). `prerequisites` / `unlocks` лучше держать согласованными с ним, чтобы граф и тултипы не расходились.

### 6.6 `requirements` — гейты и требования по уровням

```json
"requirements": {
  "unlockParents": [
    { "techId": "TECH_ICE", "level": 1 },
    { "techId": "TECH_PROPULSION", "level": 1 }
  ],
  "perLevel": [
    [ { "techId": "TECH_ICE", "level": 1 }, { "techId": "TECH_PROPULSION", "level": 1 } ],
    [ { "techId": "TECH_ICE", "level": 1 }, { "techId": "TECH_PROPULSION", "level": 1 } ],
    [ { "techId": "TECH_ICE", "level": 2 }, { "techId": "TECH_PROPULSION", "level": 2 } ]
  ]
}
```

#### `unlockParents[]` — **ключевой уровень появления**

Пока **все** родители из списка не достигли указанного `level`, технология:

- на дереве: карточка «неизвестная» (жёлтые полосы, `?`, без модалки);
- в «Открывает» у родителя: тоже unknown / без перехода;
- `isTechRevealed() === false`.

| Поле | Смысл |
|------|--------|
| `techId` | Id родительской технологии |
| `level` | Минимальный уровень родителя для **раскрытия** карточки ребёнка |

Несколько родителей = **AND** (нужны все).

#### `perLevel[]` — требования на шаг `current → current+1`

- Индекс массива = **текущий** уровень ребёнка.  
  `perLevel[0]` — условия для 0→1, `perLevel[1]` — для 1→2, …
- Каждый элемент — массив `{ techId, level }` (AND внутри шага).
- `prereqsMet()`: карточка раскрыта **и** все записи `perLevel[currentLevel]` выполнены **и** не max.
- Если шаг недоступен, исследование не стартует; статус «Не выполнены требования»; вложенные очки на этот шаг сбрасываются (анти-фальстарт).

Типичный паттерн «ребёнок не обгоняет родителя»:

- 0→1 и 1→2: родитель ≥ 1  
- 2→3: родитель ≥ 2  
- 3→4: родитель ≥ 3  
- …

Можно требовать **нескольких** родителей с разными порогами на одном шаге.

### 6.7 `stats[]` — отображаемые характеристики (опционально)

Не у всех технологий есть. Рисуются в правом нижнем блоке модалки (`technologiesExtras.js`).

```json
"stats": [
  {
    "id": "STAT_ICE_HP",
    "polarity": "positive",
    "name": { "ru": "Мощность", "en": "Horsepower", "de": "Leistung" },
    "unit": { "ru": "л.с.", "en": "hp", "de": "PS" },
    "values": [0, 45, 60, 78, 100, 125, 155, 195, 240]
  }
]
```

| Поле | Смысл |
|------|--------|
| `id` | Стабильный id характеристики (**для будущей привязки к игре**: бонусы юнитам, зданиям и т.д.) |
| `polarity` | `"positive"` → зелёный ▲ у «будущего» значения; `"negative"` → красный ▼ (даже если число растёт, напр. расход Вт / вес) |
| `name` | Локализованное имя строки |
| `unit` | Локализованная единица **или** строка (`"%"`). Пишется рядом со значением |
| `values` | Массив чисел: индекс = **уровень технологии**. `values[0]` — при level 0, `values[1]` — level 1, … Длина обычно `maxLevel + 1` |

**Текущее** значение = `values[level]` (всегда, если tech раскрыта).  
**Будущее** = `values[level + 1]` показывается только если:

- уровень не максимальный, **и**
- курсор над «Улучшить» **или** технология сейчас `researching`.

Пока `stats` **не влияют** на геймплей — только UI. Не ломай `id`, когда начнутся эффекты.

## 7. Рантайм: `state.techProgress`

Не в JSON. Пишется в сейв (`captureTechProgressSnapshot` / `applyTechProgressSnapshot`).

```js
state.techProgress[techId] = {
  level: 0,        // текущий уровень
  invested: 0,     // уже вложенные ед. технологий в текущий шаг
  researching: false
}
```

| Поле | Смысл |
|------|--------|
| `level` | Синхронизируется в `tech.level` для отображения |
| `invested` | Прогресс бара; при невыполненных требованиях на шаг → **0** |
| `researching` | Участвует в пуле: глобальный tech/min **делится поровну** между всеми с `researching: true` |

Пул = сумма `calcLocationTechProduction` по телам (рецепт «Научные открытия» и аналоги). Учитывается `timeSpeed`.

Сейв v2.3+: ключ `techProgress` в снимке сессии. Есть защита от гонки «apply до загрузки catalog» (`_pendingTechProgressSnap`).

## 8. Граф (`technologiesGraph.js`)

Рёбра собираются из:

1. `prerequisites` / `requirements.unlockParents` (направление parent → child)  
2. `unlocks` (parent → child)  
3. только если **оба** конца есть в текущей категории на экране  

Крепление: **левый/правый бок** карточки, несколько рёбер слегка разводятся по Y.

| CSS-состояние | Когда | Вид |
|---------------|-------|-----|
| `locked` | ребёнок ещё не `isTechRevealed` (и родитель не качается) | бледно-серый, без анимации |
| `boost` | качается родитель **или** ребёнок (в т.ч. к ещё скрытому ребёнку) | яркий cyan, быстрый «конвейер» |
| `active` | ребёнок открыт, никто из пары не researching | мягкий бирюзовый, медленный поток |

Состояния обновляются на тике (`refreshTechLinkStates`) без полной пересборки SVG.

## 9. UI-блоки (кратко)

| Место | Данные |
|-------|--------|
| Сайдбар | `categories` |
| Дерево | `groups` + `technologies` текущей категории; `column`/`row` |
| Хэдер панели | поток tech/min; чипы `researching` (extras) |
| Модалка: этап | `stageRanges` + `stageDefs` + `level`/`maxLevel` |
| Модалка: улучшить | `levelCosts`, `invested`, `researching`, `prereqsMet` |
| Модалка: требует | `getReqsForNextLevel` / fallback `unlockParents`; «на уровне: N» |
| Модалка: открывает | `getUnlockEntries` (unlocks + дети с этим unlockParent) |
| Модалка: характеристики | `stats[]` (extras) |
| Неизвестная карточка | `!isTechRevealed` → нет клика, нет модалки |

Карточки в «Требует / Открывает»: **горизонтальный** flex + wrap (несколько в ряд, перенос на следующую строку).

## 10. Чеклист новой технологии

1. Выбрать `id`, `categoryId`, `groupId`, `column`, `row`, `image`.  
2. `name` / `description` на ru/en/de.  
3. `maxLevel` + `levelCosts` длины `maxLevel` (цены шагов 0→1 …).  
4. `level: 0` (если не стартово изучена).  
5. `stageRanges` покрывают 0…maxLevel без дыр.  
6. `requirements.unlockParents` — когда карточка вообще появляется.  
7. `requirements.perLevel[0..maxLevel-1]` — кто и какого уровня нужен на каждый шаг.  
8. Согласовать `prerequisites` / у родителей `unlocks` (граф + UX).  
9. По желанию `stats[]` с `id`, `polarity`, `values[maxLevel+1]`.  
10. Проверить дерево, граф, модалку, сейв/лоад, блокировку исследования.

## 11. Типичные ошибки

| Симптом | Вероятная причина |
|---------|-------------------|
| Карточка всегда «?» | `unlockParents` не выполнены или `discovered: false` |
| Можно качать «через» родителя | дырка в `perLevel` (слабый порог) |
| Граф не рисуется | родитель в **другой** категории (на экране только текущая) |
| Прогресс слетает при load | смотри pending snapshot / не сбрасывать `researching` до catalog |
| `invested` копится при закрытых reqs | должен срабатывать сброс фальстарта в тике/панели |
| Этап «не тот» цвет | неверные диапазоны `stageRanges` vs `stageDefs` |
| Пустой блок характеристик | нет `stats` или tech не revealed |

## 13. Интеграция: скорость космических юнитов (`unitSpaceSpeed.js`)

Мини-связка «стат технологии → полёт в космосе».

| Элемент | Где |
|---------|-----|
| Базовые `flightSpeed` / `systemFlightSpeed` | `units.json` (для Бурана уменьшены в **800** раз относительно старых 0.35 / 4.5) |
| Тип двигателя | `engineType`: `"rocket"` |
| Технология / стат | `engineTechId`: `TECH_ROCKET_ENGINE`, `engineStatId`: `STAT_ROCKET_THRUST` (кН) |
| Множитель | `thrustKnToSpeedMultiplier(F)`: при `F = 0` → `MIN_ENGINE_MULT` (0.35); при `F = 750` кН → `SPACE_SPEED_NERF` (800) ≈ прежняя скорость |
| Снимок на юните | `engineThrustKn`, `engineSpeedMult` |
| Обновление снимка | только если юнит **не** в `flying` / `systemFlying` / `launching` / `landing` (в технопорте или `orbit` без манёвра) |
| Старт манёвра | `lockUnitEngineForManeuver` — фиксирует тягу до конца полёта/взлёта |

Формула множителя (безразмерная):

```
t = clamp(thrustKn / 750, 0, 1)
mult = 0.35 + (800 - 0.35) * t^0.85
effectiveSpeed = baseSpeedFromJson * mult
```

Так тяга в **кН** не подставляется в мир напрямую: она нормируется к эталону макс. стата и даёт осмысленный прогресс от «еле ползёт» до «как раньше на фулл-техе».
